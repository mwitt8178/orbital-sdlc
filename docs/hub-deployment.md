# Hub Deployment Guide

> Step-by-step guide for self-hosting the Orbital Hub.

---

## Overview

The Orbital Hub is the central data plane for multi-operator collaboration.
It runs as a Docker Compose stack containing:

- **orbital-hub** — Fastify/Node.js application (the hub itself)
- **hub-postgres** — Postgres 16 for shared data
- **nginx** — TLS termination, HTTP-to-HTTPS redirect, WebSocket proxy

Each operator's laptop runs a local Orbital instance that connects to the hub
for shared data (tasks, channels, memory, audit events). Compute stays local —
workers run on the operator's machine using the operator's Anthropic API key.

---

## Prerequisites

- Docker Engine 24+ and Docker Compose v2 (`docker compose`, not `docker-compose`)
- A domain name pointing to your host (e.g. `orbital.team.dev`)
- A TLS certificate for that domain (or use the auto-generated self-signed cert for dev/testing)
- Ports 80 and 443 open inbound
- At least 2 GB RAM, 20 GB disk

## Quick Start (10 minutes)

### 1. Clone the repository

```bash
git clone https://github.com/orbital-oss/orbital.git
cd orbital
```

### 2. Bootstrap

Run the bootstrap script. It generates the master key, Postgres password, and
a self-signed TLS cert, then writes everything to `.env`:

```bash
ORBITAL_HOSTNAME=orbital.team.dev bash scripts/hub-bootstrap.sh
```

Output example:

```

  => Generating Postgres password...

  => Writing .env...
     ✓ .env written at /path/to/orbital/.env
  => Creating Docker secrets directory...
     ✓ secrets/hub_master_key written (chmod 600)
  => Generating self-signed TLS certificate for orbital.team.dev...

    https://orbital.team.dev/join/eyJ0eXAi...

  On your laptop, run:
    orbital join https://orbital.team.dev/join/eyJ0eXAi...

  To start the full stack:
    docker compose -f docker-compose.hub.yml up -d

  Hub will be available at: https://orbital.team.dev
  Health check:             https://orbital.team.dev/health
```

### 3. Start the stack

```bash
docker compose -f docker-compose.hub.yml up -d
```

This starts Postgres, then the hub (waits for Postgres health check), then nginx.

### 4. Verify

```bash
# Check all containers are healthy
docker compose -f docker-compose.hub.yml ps

# Health check
curl -f https://orbital.team.dev/health

# Expected:
# {"status":"ok","mode":"hub","uptime":12.3,"timestamp":"..."}
```

### 5. Connect your laptop

On your operator laptop:

```bash
orbital join https://orbital.team.dev/join/eyJ0eXAi...
```

This generates an Ed25519 keypair on your laptop, registers with the hub, and
saves your hub connection URL to `~/.orbital/config/install.json`.

## Environment Variables

Required (set by `hub-bootstrap.sh`):

| Variable | Description |
|---|---|
| `ORBITAL_HUB_MASTER_KEY` | 64-hex-char AES master key. Never lose this. |
| `HUB_POSTGRES_PASSWORD` | Postgres password (generated by bootstrap). |
| `ORBITAL_HOSTNAME` | Public hostname (e.g. `orbital.team.dev`). |

Optional:

| Variable | Default | Description |
|---|---|---|
| `ORBITAL_PORT` | `4000` | Hub service port (internal). |
| `HUB_POSTGRES_PORT` | `5433` | Postgres exposed port on host. |
| `LOG_LEVEL` | `warn` | Logging verbosity (`trace`/`debug`/`info`/`warn`/`error`). |
| `ORBITAL_HUB_TENANT_ID` | Generated UUID | Default tenant ID for the initial install. |
| `CORS_ALLOWED_ORIGINS` | `https://<HOSTNAME>` | Comma-separated list of CORS origins. |
| `ORBITAL_OWNER_TOKEN` | (none) | Owner API token for hub admin endpoints. |
| `BACKUP_DIR` | `./backups` | Local backup directory. |
| `BACKUP_S3_BUCKET` | (none) | S3/R2 bucket for remote backup upload. |
| `BACKUP_RETENTION_DAYS` | `30` | How many days of local backups to keep. |

## TLS Certificates

### Self-signed (development / internal use)

The bootstrap script generates a self-signed cert automatically. Browsers will
warn about it. For production, replace with a real cert.

### Let's Encrypt (recommended for production)

Using certbot standalone (stop nginx first, then restart):

```bash
# Install certbot
sudo apt install certbot

# Stop nginx to free port 80
docker compose -f docker-compose.hub.yml stop nginx

# Get certificate
sudo certbot certonly --standalone -d orbital.team.dev

# Copy cert to nginx/certs/
sudo cp /etc/letsencrypt/live/orbital.team.dev/fullchain.pem nginx/certs/cert.pem
sudo cp /etc/letsencrypt/live/orbital.team.dev/privkey.pem nginx/certs/key.pem
sudo chown $USER:$USER nginx/certs/*.pem

# Start nginx
docker compose -f docker-compose.hub.yml start nginx
```

For automatic renewal, add to crontab:

```cron
0 0 1 * * cd /path/to/orbital && \
  docker compose -f docker-compose.hub.yml stop nginx && \
  certbot renew --standalone && \
  cp /etc/letsencrypt/live/orbital.team.dev/fullchain.pem nginx/certs/cert.pem && \
  cp /etc/letsencrypt/live/orbital.team.dev/privkey.pem nginx/certs/key.pem && \
  docker compose -f docker-compose.hub.yml start nginx
```

## Hub Admin UI

When running in hub mode, the Hub Admin UI is available at `/hub-admin`.

Access is gated by an owner token. Set `ORBITAL_OWNER_TOKEN` in your `.env`:

```bash
echo "ORBITAL_OWNER_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose -f docker-compose.hub.yml restart orbital-hub
```

Then visit `https://orbital.team.dev/hub-admin` and enter your token.

Tabs:

- **Health** — version, uptime, DB status, tenant count
- **Installs** — registered operator laptops, revoke button
- **Audit Tail** — live stream of audit events, filterable
- **Backup** — trigger backup, view backup history

## Backup

### Automated backups

Schedule `hub-backup.sh` to run daily:

```bash
# Cron: daily at 3am UTC
0 3 * * * cd /path/to/orbital && \
  DATABASE_URL="postgres://orbital:<password>@localhost:5433/orbital_hub" \
  bash scripts/hub-backup.sh >> /var/log/orbital-backup.log 2>&1
```

Backups are saved to `./backups/` as `orbital-hub-backup-<timestamp>.sql.gz.enc`.

### Upload to S3/R2

```bash
export BACKUP_S3_BUCKET=my-backup-bucket
export BACKUP_S3_PREFIX=orbital-hub/
# For Cloudflare R2:
export BACKUP_S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
export AWS_ACCESS_KEY_ID=<r2-access-key>
export AWS_SECRET_ACCESS_KEY=<r2-secret-key>

bash scripts/hub-backup.sh
```

### Manual backup

```bash
bash scripts/hub-backup.sh
```

### Restore

See `docs/hub-rollback.md` for the full restore procedure.

Quick restore:

```bash
bash scripts/hub-restore.sh --backup=./backups/orbital-hub-backup-20250101T120000Z.sql.gz.enc
```

## Key Rotation

The hub master key encrypts all backups. Rotate it annually or immediately if
it may have been compromised.

```bash
# With confirmation prompt
bash scripts/hub-rotate-master-key.sh

# Automated (CI/scheduled)
bash scripts/hub-rotate-master-key.sh --yes-i-know-what-i-am-doing
```

After rotation:

1. Restart the hub: `docker compose -f docker-compose.hub.yml restart orbital-hub`
2. Verify health: `curl -f https://orbital.team.dev/health`
3. After 24h (default verification window): `rm secrets/hub_master_key.prev`

The old key is kept in `secrets/hub_master_key.prev` for 24h so any in-flight
operations signed with the old key can still verify.

See `docs/hub-rollback.md` for the full key rotation rollback procedure.

## Upgrading the Hub

```bash
# Pull the latest image
docker compose -f docker-compose.hub.yml pull orbital-hub

# Restart with zero-downtime (if only one instance)
docker compose -f docker-compose.hub.yml up -d --no-deps orbital-hub

# Verify
curl -f https://orbital.team.dev/health
```

Migrations run automatically on startup.

## Troubleshooting

### Container not starting

```bash
docker compose -f docker-compose.hub.yml logs orbital-hub
docker compose -f docker-compose.hub.yml logs hub-postgres
```

### "ORBITAL_HUB_MASTER_KEY must be set"

Run bootstrap: `bash scripts/hub-bootstrap.sh`

### Postgres not ready

```bash
docker exec orbital-hub-postgres pg_isready -U orbital -d orbital_hub
```

### TLS errors

```bash
# Verify cert is in place
ls -la nginx/certs/
openssl x509 -in nginx/certs/cert.pem -text -noout | grep -E "CN|DNS"
```

### Port conflicts

Default ports: 80, 443, 5433 (Postgres). Override in `.env`:

```
HUB_POSTGRES_PORT=5434
```

### Migrations failed

```bash
DATABASE_URL="postgres://orbital:<password>@localhost:5433/orbital_hub" \
  npm run db:migrate --workspace=packages/orchestrator
```

### Hub admin returns 401

Set `ORBITAL_OWNER_TOKEN` in `.env` and restart the hub.

## Monitoring

The hub exposes:

- `GET /health` — liveness (no auth)
- `GET /health/ready` — readiness + DB connectivity (no auth)
- `GET /metrics` — Prometheus metrics (restrict in production)
- `GET /admin/health` — detailed hub health (no auth)

Recommended: wire `/health/ready` to your uptime monitor.

## Security hardening checklist

- [ ] Replace self-signed cert with CA-signed cert
- [ ] Set `ORBITAL_OWNER_TOKEN` to a strong random value
- [ ] Restrict Postgres port (5433) to localhost or firewall it
- [ ] Enable automatic Let's Encrypt renewal
- [ ] Set up backup retention policy and off-site upload
- [ ] Monitor `/health/ready` with your alerting system
- [ ] Review `nginx/hub.conf` rate limits for your traffic volume
- [ ] Back up `secrets/hub_master_key` to a secure secrets manager

## Architecture notes

For the full architecture, see `.claude/tasks/round7-multi-operator-federation/architecture.md`.

The hub holds **state and signaling** — tasks, channels, memory, audit events.
It does NOT hold secrets (Anthropic API keys, capability bundle private keys)
or compute artifacts (replay blobs, worker stdout).
